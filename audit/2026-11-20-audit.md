## 一、架构问题

### 1.1 `main.js` 是最大的结构债

**位置**：`src/main.js`，2554 行。

**规模**：

| 文件 | 行数 |
|---|---|
| `src/main.js` | 2554 |
| `src/core/canvas.js` | 592 |
| `src/core/format.js` | 406 |
| `src/core/hokusai-engine.js` | 346 |
| `src/core/history.js` | 234 |

**问题**：25 个顶层可变变量，无归属。

```
doc / docName / tool / stroke / pending / gesture / floating
dragState / colorSlot / thumbTimer / refScale / refUrl / dpr
rafId / needFrame / framePending / frameQueuedAt / navAt / dragDepth …
```

任何函数都能改任意状态。直接后果是**无法单独测试**——想测移动工具，
得先构造整个应用环境。

**职责混杂**：装配、渲染循环、工具分发、图层 UI、文件 IO、
浮层、参考图窗、控制台，全在一个文件里。

**已经造成的故障**：`gestureMove` 和 `gestureEnd` 结构高度相似，
两次用字符串替换改代码时锚点同时命中两处，把使用未定义变量的代码
插进了另一个函数，导致功能静默失效（`rotateLayer` 和浮动选区各一次）。

### 1.2 撤销模型只覆盖像素

**位置**：`src/core/history.js`；调用点 `src/main.js:393, 884, 1007, 1160`。

`beginStroke(tileCanvas)` 是唯一入口，只对像素快照。

**不被撤销覆盖的操作**：

- 新建图层 / 新建组（`main.js:1838, 1842`）
- 删除图层（`main.js:1644`）
- 图层重排、改名
- 修改不透明度、混合模式、可见性
- 蒙版的新建与删除

**后果**：误删图层无法恢复。对绘画软件这是数据丢失级缺口。

### 1.3 没有销毁路径

**位置**：`src/core/hokusai-engine.js:109, 113`。

这两处 `free()` 位于 `ensureSurface()` 内，只在**画布尺寸变化**时触发重建，
不是销毁接口。类上**没有 `dispose()` 方法**，`main.js` 也没有任何释放调用
（`grep -c "\.free()\|\.dispose()" src/main.js` → 0）。

具体泄漏点：

- `nodeById`（`main.js:1415`）只增不删，删除的图层仍被 Map 持有，
  换文档时也不清空
- 换文档时 `hk.canvas = null`（`installDocument`），本地引用断了，
  wasm 侧靠 `FinalizationRegistry` 回收，时机不可控

**影响**：单次会话内反复删除/新建图层、反复换文档，内存会持续增长，
只是增长得慢，不会立刻表现为故障。

### 1.4 变换与蒙版脱节

| 操作 | 画布 | 蒙版 | 历史快照 |
|---|---|---|---|
| 移动图层 | 移动 | 移动 | **只拍画布** |
| 旋转图层 | 旋转 | **不动** | 只拍画布 |

**位置**：`main.js` `commitMove()` 与 `rotateLayer()`。

`rotateLayer` 的注释直接写明了：

```
if (node.mask) { /* 蒙版跟着转会更复杂，先不动，留给自由变换统一做 */ }
```

**后果**：
- 移动后撤销 → 蒙版永久错位
- 旋转后 → 蒙版与内容完全脱节

## 二、安全

### 2.1 高危：Electron IPC 接受任意路径

**位置**：`native/electron/main.js` 的 `achi:read` / `achi:delete`。

渲染进程传来的路径直接使用，无白名单校验。

**风险**：渲染进程一旦被注入，可读取或删除用户权限内的任意文件。

**建议**：主进程维护「用户通过对话框选择过的路径」表，只接受表内路径。

### 2.2 中危：无 CSP，生产包暴露调试接口

**位置**：`src/main.js` `window.__achi`。

挂载了 `newDocument`、`doSave`、`rotateLayer` 等写操作。
本地应用风险有限，但属于无必要暴露的攻击面。

### 2.3 中危：保存路径语义不符

**位置**：`src/platform/fileio.js:74`。

`⌘S` 每次都弹保存对话框，没有「当前文件路径」概念，
与用户对「保存 / 另存为」的预期不符。

### 2.4 低危：导出后立即释放 ObjectURL

**位置**：`src/main.js` 导出路径。

`fileio.js:29` 已经知道要延迟 4 秒，导出没照做。Safari 上可能中断下载。

### 2.5 低危：首帧预览不透明度错误

**位置**：`src/core/hokusai-engine.js:162 vs 165`。

`overlayAlpha` 在 `this.opacity` 赋值之前写入，首帧按 100% 画，
松手才变成设定值。

### 2.6 低危：浮选区旋转历史范围不足

**位置**：`src/main.js` `commitFloating()`。

历史只覆盖原矩形，旋转后超出原框的部分撤销不掉，会留残影。

## 三、性能

### 实测数据

2480×3508 画布：

| 笔刷 | 单笔耗时 |
|---|---|
| 40px | 22ms |
| 80px | 28ms |
| 180px | 58ms |
| 300px | **92ms** |

60Hz 下 92ms 等于 5.5 帧看不到笔迹。

### 根因

笔刷计算（libmypaint 的 dab）**全部在主线程同步执行**。
dab 数量随笔刷面积增长，直接阻塞输入。

### 已优化项

- 缩略图改直绘 canvas，去掉每笔 `toDataURL()`（PNG 编码 10~30ms）
- 消除每帧 `_key.split(',')`（A4 全量 140 次字符串切分）
- `History.trim()` 从 `shift()` 循环改成 `slice()` 一次性切除（原为 O(n²)）

### 待优化

见 [PERFORMANCE.md](../PERFORMANCE.md)：v0.2 Worker 化 → v0.3 WebGL2 合成 → v0.4 LOD。

## 四、测试

### 现状

`find . -name "*.test.js" -o -name "*.spec.js"` → **无结果**。

仅有的验证手段是 `main.js` 里两个手动自测函数：

- `selfTestImage()` — 导入图片
- `selfTestRoundtrip()` — 文件往返（2026-11-20 已从「只比尺寸」加强为「逐瓦片比像素」）

### 为什么这是问题

`DEVNOTES.md` 记录了三类「数据层对、用户看到的不对」的故障：

1. rAF 死锁 — 瓦片有内容，屏幕没变化
2. 打开文件空白 — 瓦片有内容，`doc.off` 是空的
3. 组/蒙版只有左上角正确 — 导出对，视口错

这三类**冒烟测试都发现不了**。

### 建议

把现有的一次性 CDP 脚本固化成可重复执行的测试，
断言对象是 `doc.off`（合成层）而不是图层瓦片。

## 五、修复建议顺序

按「不做会出什么事」排序：

| 优先级 | 事项 | 理由 |
|---|---|---|
| 1 | 撤销覆盖结构变更 | 误删图层无法恢复，数据安全 |
| 2 | 拆 `main.js`，状态收进对象 | 为测试铺路，减少跨函数误改 |
| 3 | 像素级测试固化 | 上面三类故障全靠手动发现，不可持续 |
| 4 | IPC 路径白名单 | 安全 |
| 5 | 补销毁路径并接入生命周期 | 长时间使用内存增长 |
| 6 | 变换与蒙版同步 | 功能正确性 |
