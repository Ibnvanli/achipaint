## 二、逐条说明

### 1.2 撤销只覆盖像素（已修）

审计结论准确：`beginStroke(tileCanvas)` 是唯一入口，只管像素。
新建 / 删除 / 重排 / 改名 / 属性修改 / 蒙版增删全部游离在撤销栈之外。

**做法**：`history` 增加结构记录，不复制像素。

```
beginStructure(doc)   → 采集图层树形态：节点引用、父节点、层内位置、各属性、蒙版引用
commitStructure(p)    → 与操作后形态比对，有变化才入栈；无变化自动丢弃
undo / redo           → 按快照重建 children 数组与属性
```

关键点在于**不复制像素**：节点被移出树时对象仍被快照引用，其画布一同保留，
撤销只需把父子关系接回去。这让一条结构记录只有数 KB，且不计入 384MB 像素上限。

接入点：`doDelete` / `onLayerDragEnd` / `addLayer` / `addGroup` / `setMaskMode` /
改名完成回调 / 不透明度滑杆（300ms 静默期合并为一条）/ 混合模式下拉框。

撤销后同步重建图层面板与缩略图 —— 结构变了只调 `redraw()` 面板会与实际不符。

### 1.3 无销毁路径（已修）

审计指出 `free()` 只在 `ensureSurface()` 内、尺寸变化时触发，类上没有销毁接口。

**做法**：`HokusaiEngine.dispose()`，可重复调用，释放 wasm 画布与全部笔刷对象。
`installDocument()` 中在挂载新文档**之前**调用（dispose 会清空 `hk.doc`），
同时清空 `nodeById`。

### 1.4 变换与蒙版脱节（已修）

| 操作 | 修复前 | 修复后 |
|---|---|---|
| 移动图层 | 蒙版移动，历史只拍画布 | 蒙版单独拍摄快照，撤销同步复位 |
| 旋转图层 | 蒙版不动 | 绕同一中心旋转，历史覆盖蒙版 |

旋转逻辑抽为 `rotateTiles(tc, deg, cx, cy)`，内容与蒙版共用同一函数，
从实现上保证两者使用相同的变换与中心点，不会再各自演化。

### 2.1 IPC 接受任意路径（已修）

**做法**：主进程维护 `authorizedPaths`，只接受用户通过对话框选定过的路径。
授权来源仅两处：`showSaveDialog` 与 `showOpenDialog` 的返回结果。

路径经 `fs.realpathSync.native` 规范化后登记，避免符号链接绕过。
未授权调用会被拒绝并留日志。

**「最近文件」的处理**：授权表只在内存中，重启后为空。用户点击最近文件是一次
明确意图，但仍需确认 —— 新增 `achi:grant`，由主进程弹确认框。
若仅凭渲染进程传入的路径就放行，授权表等于形同虚设。

### 2.4 / 2.5 / 2.6（已修）

- **2.4**：导出改为延迟 4 秒释放 ObjectURL，与 `fileio.js` 的下载兜底一致
- **2.5**：调整赋值顺序，`this.opacity` 先确定再写入 `overlayAlpha`；
  构造函数补充 `this.opacity = 1` 初始化
- **2.6**：`commitFloating()` 落回前调用 `grabRegion` 扩大快照，
  覆盖旋转 / 移动后的实际落点区域

## 三、测试（已建）

审计第 4 节的判断成立：项目此前只有两个手动自测函数，没有可重复执行的测试。

**做法**：`test/harness.js` + `test/cases/*.test.js`，`npm test` 运行。

三处设计取舍：

1. **不用 jsdom**：断言对象是真实 Canvas 像素与合成结果，jsdom 没有实现 Canvas 2D，
   用它等于测试一个假实现
2. **不引测试框架**：项目坚持无构建步骤，测试保持一致
3. **断言合成层（`doc.off`）而非图层瓦片**：审计列出的三次故障
   （rAF 死锁、打开空白、组蒙版只有左上角正确）都是「瓦片对、屏幕错」

现有 13 项用例：撤销结构变更 8 项、变换与蒙版 3 项、浮动选区与首帧不透明度 2 项。

**有效性验证**：故意退回两处修复，确认测试能报错：

| 退回的修复 | 测试输出 |
|---|---|
| `boundsOf` 改回按块网格 | 旋转前后面积偏差 48.2%（480000 → 248832） |
| `restoreTree` 不还原 `opacity` | 撤销应还原不透明度：0.3 ≠ 1 |

## 四、审计未列出、测试发现的新问题

### 旋转轴心偏移导致内容丢失（已修）

`boundsOf` 原本返回**块网格的外接矩形**。块固定 256×256，内容通常只占块的一部分，
因此包围盒最多比真实内容大 255px/边。旋转以包围盒中心为轴，中心一偏，内容就被甩出画布。

实测：800×600 画布铺满后旋转 180°，不透明像素 480000 → 248832，**丢失 48%**。

改为逐块扫描像素求真实边界后，面积保持不变。

这条恰好印证审计第 4 节的结论：这类问题冒烟测试与肉眼都难以发现，
只有在特定内容与特定角度下才暴露。

## 五、未做的项

### 1.1 拆分 `main.js`（未做）

审计将其列为优先级 2，理由是「为测试铺路」。

**部分不认同**：测试已用另一条路建成 —— 断言合成层像素，不需要先拆模块。
P3 因此不依赖 P2。

现在拆分的实际收益是「减少跨函数误改」，成本是把约 2700 行、30 个顶层可变状态
重新分配。这属于该做、但不该与数据安全修复混在同一轮的事 ——
期间所有既有功能都有回归风险，而回归验证手段刚刚建立。

已在 ROADMAP 中记录未修，规模与状态分布同步更新。

### 2.2 CSP 与调试接口暴露（未做）

`window.__achi` 上挂了 `newDocument`、`doSave`、`rotateLayer` 等写操作。
本地应用风险有限，但确实是可收敛的攻击面。与 CSP 一并处理更合适。

### 2.3 保存路径语义（未做）

`⌘S` 每次弹保存对话框，缺少「当前文件路径」概念。
这需要改动文件 IO 的状态模型，牵涉 `fileio.js` 与命令分发，单独处理。

### 三、性能

按 `PERFORMANCE.md` 的既定路线推进（v0.2 Worker 化 → v0.3 WebGL2 → v0.4 LOD）。
本轮未涉及。
